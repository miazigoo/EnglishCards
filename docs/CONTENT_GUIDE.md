# Руководство по содержанию (Content Guide) v3.0

Данное руководство описывает принципы создания, редактирования и верификации карточек и учебных материалов в проекте EnglishCards.

---

## 1. Структура карточки (`card.schema.json`)

Все карточки хранятся в едином источнике `content/cards.json` и строго проверяются по схеме `content/schema/card.schema.json`.

Обязательные поля:
- `schema_version`: версия схемы (текущая — `3`).
- `card_id`: стабильный строковый идентификатор. Не зависит от позиции в списке или номера категории. Пример: `python.str.rsplit.directional`, `workplace.verb.collaborate`.
- `legacy_ids`: массив прежних числовых ID для миграции прогресса.
- `display_term`: точное написание термина или метода (например, `rsplit()`).
- `meaning_ru_short`: лаконичный и точный перевод на русский язык (например, «разделяет строку по разделителю, выбирая разделения справа»).
- `explanation_ru`: ясное педагогическое объяснение логики работы.
- `examples`: массив контекстных примеров (минимум 1 предложение).
- `practice`: конфигурация шаблонов практики, подсказки для обратного перевода (`ru_to_en`), список принимаемых ответов, целевое слово для cloze-теста.
- `qa`: статус ревизии (`draft`, `ready`, `excluded`, `split`) и уровень проверки (`automated`, `model_reviewed`, `human_reviewed`).

## 2. Запрещенные антипаттерны контента (P0 Quality Gates)

При валидации контента строго запрещены:
1. **Шаблонный мусор**:
   Фразы вида `«Термин '...' обозначает ключевую сущность или архитектурный паттерн»` категорически недопустимы. Запрещены искусственные заглушки вроде `class RsplitService:` или `class IssubclassService:`.
2. **Смешение алфавитов в подсказках транскрипции (`ru_hint`)**:
   Запрещены слова со смешанными латинскими буквами в кириллической строке (например, `iссuбcлaсс`, `рeквест`). Все русские подсказки должны содержать исключительно кириллицу.
3. **Фиктивные транскрипции IPA**:
   Запрещено подставлять сырой идентификатор в косых чертах (например, `/rsplit/` или `/issubclass/`). Если верифицированной IPA транскрипции нет, поле `ipa` должно быть `null`.
4. **Синтаксические ошибки в коде**:
   Все примеры Python должны успешно парситься `ast.parse()` и быть совместимы с Python 3.12+.
   Запрещено передавать именованные аргументы туда, где они не поддерживаются (например, `getattr(obj, name, default=0.0)` — ошибка, должно быть `getattr(obj, name, 0.0)`).
5. **Смешение понятий с одинаковым именем**:
   Встроенные методы языка и методы внешних библиотек должны быть разделены (например, `python.builtins.filter` и `django.queryset.filter`).

## 3. Эталонные карточки (Benchmark Cards)

- **`rsplit()`**:
  - Разбор: `right` (справа) + `split` (разделить).
  - Перевод: «разделить справа».
  - Сравнение со `split()`:
    ```python
    filename = 'report.final.csv'
    assert filename.rsplit('.', 1) == ['report.final', 'csv']
    assert filename.split('.', 1) == ['report', 'final.csv']
    ```
- **`zip()`**:
  - Объединение по позициям: первый с первым, второй со вторым.
  - Пример: имена и оценки `[('Anna', 90), ('Max', 85)]`.
  - Завершение на кратчайшей коллекции.
- **`issubclass()`**:
  - Проверка наследования классов:
    ```python
    class Animal: pass
    class Dog(Animal): pass
    assert issubclass(Dog, Animal) is True
    assert issubclass(Animal, Dog) is False
    ```
- **`getattr()`**:
  - Безопасное динамическое чтение атрибута с позиционным значением по умолчанию: `getattr(order, 'total_weight', 0.0)`.

## 4. Микроуроки (`content/lessons/`)

Проект содержит 12 микроуроков по 3–5 минут:
- Артикли в техническом контексте (`a/an` vs `the`).
- Исчисляемость (`data`, `code`, `information`).
- `Do` vs `Make` в разработке ПО.
- `Say` vs `Tell` в командной коммуникации.
- Фразовые глаголы (`look at`, `look for`, `look into`).
- Управление предлогами (`depend on`).
- Модальные глаголы (`must`, `have to`, `should`).
- Вежливые просьбы (`could you`, `would you mind + V-ing`).
- Отрицания (`neither ... nor`, отсутствие двойного отрицания).
- Порядок слов в вопросах (прямые vs косвенные).
- Времена в баг-репортах (`Past Simple` vs `Present Perfect`).
- Логические связки в документации (`however`, `therefore`, `although`).

Каждый урок содержит:
1. `rule_ru`: четкое, компактное теоретическое правило.
2. `examples`: 2–3 примера из реальной разработки с подсветкой ключевой фразы.
3. `exercises`: ровно 3 тестовых мини-упражнения с объяснением правильного ответа.
